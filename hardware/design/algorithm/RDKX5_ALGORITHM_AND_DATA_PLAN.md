# RootScope｜RDK X5 算法与数据冻结计划

> 状态：`H12_LOCAL_BASELINE_COMPLETE / SIMULATED_ONLY / DATA_SEED_ROUND1_COMPLETE / NOT_TRAIN_READY`  
> 版本：v1.0｜2026-07-15  
> 范围：所有代码、数据、模型和证据只进入 `adventurex/`，不依赖 XRD 主目录运行。

## 0. 先拍板

三天内不做“识别很多沙漠植物物种”的大而散模型。P0 冻结为三种**可见形态**加拒答：

| 模型标签 | 现场中文 | 可见依据 | 夹具演示映射 |
|---|---|---|---|
| `grass_clump` | 草丛型 | 簇生、细长叶片、低矮轮廓 | `Profile-A → Z1` |
| `low_shrub` | 低矮灌木型 | 多分枝、团状冠幅、无明显主干 | `Profile-B → Z2` |
| `young_tree` | 幼树苗型 | 明显主干和小型树冠 | `Profile-C → Z3` |
| `unknown` | 未知/不合格 | 裸沙、石块、空白纸、手、动物、模糊、遮挡、混合植物 | 拒绝执行 |

这三个标签只描述相机看到的形态，不能直接推出真实根深、需水量或农学处方。`Z1/Z2/Z3` 只是 RootScope 透明卡匣中的演示坐标。

P1 可把芨芨草、油蒿/黑沙蒿、白刺、梭梭、胡杨幼树、柽柳型作为物种元数据和讲解案例，但三天版模型不承诺精确到物种。Kew Plants of the World Online 与植物智仅用于核对分类和形态，不默认获得其中网页图片的训练/再发布权。

## 1. 为什么这样做

- 固定相机、固定卡片区域不需要先上 YOLO；小型分类器更容易在 72 小时内训练、量化、上板和复测。
- 稳定演示仍保留显式场景卡/标签入口；BPU 模型只有过冻结测试门后才能成为正式感知源，否则显示为 `shadow`。
- 视觉模型负责“看见什么”，状态机负责“是否允许执行”，本地大模型只负责“把已有证据讲明白”。
- 主演示图片必须来自完全留出的图片 ID。把训练图打印出来只能算 `DEMO_KNOWN_CARD`，不能冒充泛化能力。

## 2. X5 软件总体架构

```text
固定 UVC 相机
  ├─ CPU/OpenCV：卡片定位、透视校正、亮度/模糊/遮挡质量门
  ├─ RDK X5 BPU：grass_clump / low_shrub / young_tree / unknown
  └─ CPU/OpenCV：透明沙体目标 ROI 的前后湿润变化验证
                       │
                  确定性状态机
               （唯一命令所有者）
                       │ USB-TTL / 0xAA55
                       ▼
                   STM32F407
      三泵互斥 / HX711 / 急停 / 漏水 / 卡匣 / 硬超时
                       │
              JSONL 证据链 + Dashboard
                       │
         本地小模型 + RAG：只读解释，不拥有泵权限
```

RDK X5 的 BPU 部署以 D-Robotics 官方 [`rdk_model_zoo`](https://github.com/D-Robotics/rdk_model_zoo) 的 X5 分支、分类样例和 `hobot_dnn` 运行方式为依据；最终必须记录实际 backend，不能因为存在 `.bin` 就声称 BPU 已运行。

### 2.1 权限边界

| 模块 | 可以做 | 绝对不能做 |
|---|---|---|
| BPU 视觉 | 输出类别、置信度、拒答原因 | 直接发泵命令、修改剂量 |
| OpenCV | 质量门、卡片矫正、湿润 ROI 证据 | 单独宣布物理闭环完成 |
| 状态机 | 组合安全门并生成唯一任务命令 | 跳过 F407 ACK 或故障锁存 |
| F407 | 三泵互斥、计量、硬超时、急停 | 接受旧任务/错身份/重复序号 |
| 本地 LLM | 解释结构化事实、引用本地资料 | 生成执行许可、清急停、虚构根深或节水率 |
| Dashboard | 展示、触发受控任务、导出证据 | 绕过状态机直接控制 GPIO/串口 |

## 3. 数据集合同：自然照片域与打印卡域分开

### 3.1 四个数据域

| `domain` | 用途 | 是否可训练 | 关键约束 |
|---|---|---:|---|
| `natural_web` | 获得形态多样性 | 是，人工审核后 | 逐张来源、作者、许可证、哈希 |
| `print_demo_source` | 最终主演示卡母图 | 否 | 从采集之初按 source ID 完全留出 |
| `printed_capture` | 最终 UVC、灯光、距离下复拍 | 只进入单独打印域测试；主演示母图复拍不得训练 | 记录打印机、纸张、尺寸、光照、姿态 |
| `local_negative` | 裸沙、卡边、手、遮挡、空卡等未知类 | 是 | 由团队在真实夹具现场补拍，最重要 |

### 3.2 严禁的数据泄漏

同一原始图片及其裁剪、压缩、增强、打印和复拍必须属于同一 `source_group`。训练/验证/测试/打印演示按来源页面与原图 ID 分组，不能随机按文件切分。

必须分别报告：

1. 冻结自然照片测试集；
2. 独立打印卡复拍测试集；
3. `unknown` 拒答测试；
4. X5 CPU 与 BPU golden replay 一致性。

不得把四者混成一个“总准确率”。

### 3.3 图片来源与许可证

首批只从 Wikimedia Commons 下载。Commons 的 [ImageInfo API](https://www.mediawiki.org/wiki/API:Imageinfo) 和[机器可读元数据](https://commons.wikimedia.org/wiki/Commons:Machine-readable_data)可返回文件页、作者、许可和原图信息；但每张仍需人工复核文件说明页。

默认白名单：

- `CC0` / `Public Domain`；
- `CC BY 4.0` 及可明确署名的 CC BY 版本；
- `CC BY-SA` 可进入隔离候选池，衍生图与打印卡须继续保留相同/兼容许可和署名。

直接排除：NC、ND、All Rights Reserved、许可/作者缺失、搜索引擎缩略图、商品页、水印图库、来源只写“网络”的图片。

每个 manifest 条目至少保存：类别、物种提示、source group、原始标题/pageid、文件页、下载 URL、作者、许可证名称/URL、获取日期、尺寸、SHA-256、审核状态、数据域、split 和 `print_eligible`。

### 3.4 数量与当前阶段

- D0 种子集：每类 12–20 张，仅用于检查类别定义、来源流程和打印可辨识性；不是可直接训练的完成集。
- D1 训练候选：每个目标类争取 150–300 张唯一且审核通过的图片，`unknown` 150–300 张，质量优先于数量。
- D2 本地采集：至少 3 类 × 2 张留出母图 × 10 种摆放，加 20 个 unknown/遮挡/反光/模糊案例。
- 若 H36 前数据质量不足，BPU 保持 `shadow`；P0 继续使用显式卡标签完成可靠闭环。

## 4. 打印卡冻结规范

1. 每类准备 8–12 张候选母图，最终冻结 2 张主演示卡和 1 张备用卡；每张来自不同 source group。
2. 三类必须使用相同哑光纸、相同图片尺寸、相同白边、相同打印质量；模型裁剪区内不得出现类别文字、二维码或彩色边框。
3. 卡片外部可有编号/二维码用于证据追溯，但若它参与决策，Dashboard 必须明确显示 `perception_source=tag`。
4. 每张卡背面或统一署名页写：类别、物种提示、作者、来源页、许可证、是否裁剪。
5. 最终相机、支架、灯光和距离冻结后复拍；覆盖正视、±10°、±20°、近/远、轻微阴影和轻微遮挡。
6. 主演示卡需连续 10/10 正确，六张留出卡总计至少 57/60；unknown 至少 18/20 正确拒答。未过门则退回标签入口。

## 5. 视觉模型路线（现在只冻结计划，不写训练代码）

### P0 模型

- 输入：透视校正后的固定卡片 ROI，RGB `224×224`；
- 网络：ImageNet 预训练 `MobileNetV3-Small` 四分类；
- 输出：三种形态 + unknown；
- 拒答：最高分阈值、top1-top2 margin、图像质量门三者共同决定；
- CPU 基线：PC FP32 ONNX；
- BPU 路径：静态 ONNX → 校准集 → mapper/checker/makertbin → X5 `hobot_dnn`；
- 运行记录：模型 SHA-256、配置 SHA-256、backend、延迟、top1、score、拒答原因。

固定卡片 ROI 先分类，不在三天版叠加检测、分割、姿态估计和物种识别。赛后若转向真实自然沙地，再升级为 YOLO/分割和多目标场景；那是不同数据合同，不能拿打印卡结果代替。

### 资格门

| 门 | 目标（不是当前成绩） | 不通过的处理 |
|---|---|---|
| 自然域冻结测试 | macro-F1 `≥0.85` | 不宣传自然场景泛化 |
| 100 图 CPU/BPU golden replay | top1 一致率 `≥98%`，score 差 p99 `≤0.10` | BPU 标 `not-qualified` |
| 打印卡真机 | `≥57/60`，主演示卡各 `10/10` | 正式入口改为 tag |
| unknown 拒答 | `≥18/20` | 不允许视觉自动 admission |
| 后端证据 | 日志确认为 `hobot_dnn` | 只写 CPU/模拟，不写 BPU |

## 6. 本地大模型与项目知识库

本地 LLM 是“讲解员”，不是“灌溉决策器”。建议只部署一个中文小模型，CPU 上用 llama.cpp；BPU 优先留给视觉，避免资源争抢。

### 6.1 只允许输入的结构化字段

```text
plant_morphology, perception_source, backend_actual,
confidence, reject_reason, demo_profile, channel,
target_mass, measured_mass_loss, wetting_score,
completion_class, safety_flags, retrieved_sources
```

### 6.2 输出固定为六段

1. 相机识别到了什么；
2. 系统加载了哪个“演示 Profile”；
3. 本轮质量与湿润证据是什么；
4. 为什么通过或拒绝；
5. 受控夹具与农学边界；
6. 引用的本地资料编号。

输出必须通过 JSON Schema；超时、解析失败或引用缺失时自动降级为确定性模板。LLM 无串口句柄、无状态机写权限、无泵控制 API。

知识库只收入可追溯内容：RootScope 项目说明、硬件安全边界、演示 Profile 定义、植物形态资料、灌溉基础资料及逐条来源。不能把大模型生成文本反向当作事实来源。

## 7. 从 XRD 复用什么

复用的是经过验证的方法，并复制到 AdventureX 内形成独立实现：

- `0xAA55 + type + len + payload + sum8` 帧壳、ACK、心跳、身份新鲜度和重放拒绝思想；
- `/dev/F407` 固定别名方法与串口协议合同测试；
- 追加式 JSONL、线程锁和 SHA-256 哈希链；
- `hobot_dnn` 模型加载/forward、ONNX 导出和校准清单方法；
- Dashboard 健康状态、真实 backend 标记、离线页面；
- llama.cpp 健康检查、结构化输出和模板降级。

必须为 RootScope 新写：三泵/HX711 消息和固件、植物数据集与模型、卡片质量门、沙体湿润 ROI、状态机、Dashboard schema、灌溉讲解知识库及全部测试。

禁止带入：Nav2、SLAM、LiDAR、深度相机、`cmd_vel`、里程计、MPPI、升降台、电磁铁、XRD/PL 模型和材料领域提示词。AdventureX 运行时不得 import XRD 主目录。

# RootScope 公开与保留边界

## 为什么不是完整整机仓库

RootScope 同时涉及竞赛原创、第三方数据许可、模型再分发限制和真实执行器安全。
把整个现场目录直接公开会泄露凭据、模型、数据、设备身份和可操作的泵控链，也会让
未经风险评估的代码被直接接到硬件上。

因此本仓库采用 **open-core public reference**：

- 公开系统思想、接口语义、事实边界和 fail-closed 参考测试；
- 保留足以复刻现场作品的模型、参数、数据、固件和部署资产；
- 公开代码本身可运行，但只能生成抽象 `proposal`；
- 公开代码没有任何真实设备写能力。

## 公开内容

| 类别 | 内容 |
|---|---|
| 架构 | RDK X5 / STM32 权限分层、证据链和故障方向 |
| 算法 | RootSight、RootMind、RAG2、RootScope-Ω 的公开技术说明 |
| 代码 | 抽象 EvidenceBundle、ActionProposal、确定性 HOLD 门和回执哈希 |
| 测试 | OOD、冲突、过期、非目标、设备不安全和 LLM 零权限 |
| 结果 | 已验证现场结果与明确真实性边界 |

## 保留内容

| 类别 | 不公开内容 |
|---|---|
| 凭据 | Qwen、DeepSeek、云服务、VPS、GitHub、SSH 等任何密钥 |
| 模型 | ONNX/HBM/GGUF/SafeTensors/LoRA、转换缓存与量化产物 |
| 数据 | 训练/验证/留出集、现场抓拍、模板图、RAG 原始语料与提示词 |
| 视觉 | 精确阈值、特征模板、标定矩阵、增强策略和真实运行配置 |
| 决策 | 生产 RB-VoE、Safety Compiler、评分函数、故障矩阵和策略配置 |
| 控制 | STM32 固件、引脚、串口帧、解锁/心跳/时序和执行器适配器 |
| 部署 | X5/VPS 一键部署、systemd、udev、防火墙、网络和设备身份 |
| 证据 | 未脱敏的日志、回执、哈希树、设备路径、IP 和现场账户信息 |

## 如何理解“开源”

Apache-2.0 只覆盖本仓库中实际存在的源代码。未发布的代码和资产没有因为
这个仓库而自动获得许可。RootScope 名称与视觉标识也不在代码许可证授权范围内。

## 复现范围

你可以复现：

- 合成证据的 fail-closed 逻辑；
- LLM 解释与动作权威隔离；
- proposal-only 数据合同；
- 确定性 JSON 回执和 SHA-256 封存。

你不能仅凭本仓库复现：

- RootScope 的现场视觉效果；
- X5 BPU 部署与资源编排；
- 本地 LLM 微调与 RAG2 知识库；
- STM32 探针/泵控；
- 真实灌溉机械闭环。

## 1. 最终拍板：做固定灌溉舱，不做迷你版 XRD 小车

RootScope 是一台可在桌面和展位稳定运行的固定式端侧灌溉设备。观众选择浅层、中层或深层场景，系统只打开对应的一路微型蠕动泵；储液瓶质量下降到目标值后自动停泵；固定相机再验证透明薄层沙体的目标区域是否形成新的湿润变化。只有执行 ACK、质量变化、安全门和视觉复核同时成立，界面才显示绿色终态。

> 72 小时里最有价值的不是让装置“会跑”，而是让评委亲手触发一次可重复、可失败、可解释的真实物理闭环。

冻结构型如下：

- 1×RDK X5：固定视觉、场景识别、状态机、Dashboard、证据回执；
- 1×STM32F407：三泵互斥、HX711 采样、急停/漏水/卡匣输入、心跳看门狗和硬超时；
- 1×固定 UVC 摄像头：同时覆盖场景卡与透明卡匣，不使用深度相机；
- 3×独立微型蠕动泵：分别对应 Z1/Z2/Z3 三个固定出水深度，不使用选通阀；
- 1×称重储液瓶：用质量损失作为给水量的主计量证据；
- ≥4×可替换透明薄层沙体卡匣，另备 1×空卡匣：保证连续演示与故障注入；
- 固定 2020 型材框架、白背板、恒定灯、干湿分区、接水盘、物理急停和透明防护罩。

明确不进入 P0 的内容：车轮、运动底盘、移动探针、机械臂、激光雷达、IMU、深度相机、里程计、地图与路径规划。它们既不增加本次核心证据，也会显著扩大机械、电气和调试风险。

## 2. 为什么这一版更符合 AdventureX

AdventureX 官方将活动定义为黑客松而非传统答辩比赛，并强调把想法做成可以运行、可以体验的产品；最终 Expo 面向公众、投资人、媒体和创造者开放，现场交互体验是重要组成部分。[官方 FAQ](https://faq.adventure-x.org/apply/01-before-apply/) 与 [主要活动说明](https://faq.adventure-x.org/advx/01-activities) 同时说明 2026 年细则、完整日程和现场规则仍以录取后的 Ultimate Guide 为准。

官方首页给出的核心创造窗口是 72 小时，并说明团队通常为 2–4 人，最终每队拥有展位进行公开展示；项目可为软件、硬件或其他技术创新。[AdventureX 2026 官方首页](https://adventure-x.org/)

因此，RootScope 的冲击力不靠技术名词堆叠，而靠五个评委可立即感知的亮点：

1. **一眼看懂：** 透明沙体让地下给水第一次在展位上直接可见；
2. **一次可玩：** 观众任选 Z1/Z2/Z3 场景并按 Start，30–45 秒获得结果；
3. **一条真实闭环：** 场景选择 → 安全门 → 单通道泵水 → 称重停泵 → 目标 ROI 复核 → 结构化回执；
4. **一次可信失败：** 拔掉通信、移开卡匣或按急停，泵立即失去许可并锁存；
5. **一套诚实边界：** 不虚构节水率、产量、真实植物根深或田间泛化，只证明受控夹具中的定量和到达证据。

这比“简单跑一个软件 Demo”多了真实物理执行和安全闭环，又比“三天临时做一台小车”大幅降低系统集成风险。

## 3. 产品定义与完成等级

### 3.1 本次真正证明什么

在受控透明沙体、固定光照和固定视角下，RootScope 能：

- 从场景卡或已通过门槛的本地模型得到目标层；
- 在急停、漏水、卡匣、固件身份、称重和通信均可信时授权一次灌溉任务；
- 保证任意时刻最多只有一台泵获得驱动许可；
- 用储液瓶的稳定质量差决定停泵；
- 用目标 ROI 的前后差分验证目标区域出现新的湿润变化；
- 对每轮任务记录输入来源、配置、命令/ACK、质量、视觉、安全状态和终态。

### 3.2 不做什么承诺

- Z1/Z2/Z3 是夹具坐标，不等同于植物真实根系深度；
- 质量减少证明液体离开储液瓶，不单独证明液体到达目标区域；
- 视觉变化只在冻结的相机、光照、沙体和剂量条件内有效；
- 不给出未经对照实验支持的节水率、增产率或通用农学处方；
- 本地哈希记录只能称为“可追溯、篡改可检测”，不能称第三方审计或区块链。

### 3.3 完成等级

| 完成等级 | 必须证据 | 对外显示 |
|---|---|---|
| `SIMULATED_ONLY` | 仅 UI/回放，无物理执行 | 灰色“模拟” |
| `ACTUATOR_ACK` | 新鲜 task_id、F407 身份有效、目标泵 ACK | 蓝色“执行已确认” |
| `MASS_LOSS_VERIFIED` | ACK + 稳定质量损失进入冻结容差 | 蓝色“计量已确认” |
| `TARGET_WETTING_VERIFIED` | 计量通过 + 目标 ROI 通过 + 无漏水/越区 | 绿色“目标湿润已验证” |
| `ABORTED_LOCKED` | 任一安全门失败或任务被中止并锁存 | 红色“已停止，需人工复位” |

只有最后两级中的 `TARGET_WETTING_VERIFIED` 才能作为正向闭环完成；软件字符串、泵开启时间或单一传感器都不能代替证据组合。

## 4. 30–45 秒核心 Demo

### 4.1 正向流程

1. 观众放入一张 Z1/Z2/Z3 场景卡，并将一只已复位的透明沙体卡匣推入定位槽；
2. Dashboard 显示目标层、相机新鲜度、F407 身份、急停、漏水、卡匣和称重六项安全门；
3. 观众按下实体 Start；系统冻结 task_id、目标质量、通道和视觉基线；
4. F407 只开启目标通道，实时上报质量、输入位和泵状态；
5. 达到目标质量损失或硬超时后，F407 关闭泵并返回终态 ACK；
6. 静置短暂稳定窗后，X5 比较目标 ROI 与非目标 ROI；
7. 全部通过时显示 `TARGET_WETTING_VERIFIED`、质量曲线、前后对比和短哈希回执；
8. 队员抽出卡匣并换上下一只，目标恢复时间不超过 20 秒。

### 4.2 8 秒失败演示

在新任务泵水阶段按下物理急停，或轻拉卡匣使到位开关断开：

- K1 硬件回路立即切断泵电源；
- F407 锁存安全状态并拒绝新的 `ARM_TASK`；
- X5 保持上电，记录最后遥测和失败原因；
- Dashboard 显示 `ABORTED_LOCKED`；
- 仅在故障解除、泵全关、人工 Reset 且 F407 返回 ACK 后恢复 READY。

> 失败演示不是备用节目，而是 RootScope 区别于普通“开泵 Demo”的核心展示。

## 5. 总体架构：保留上下位机，但不做车辆底层

```text
场景卡 / 透明卡匣 / 固定 UVC
                 │ USB
                 ▼
        RDK X5 上位智能与证据层
  视觉 / 状态机 / Dashboard / JSONL+SHA-256
                 │ USB → CH340/USB-TTL
                 │ 115200 8N1，3.3 V TTL
                 ▼
        STM32F407 下位执行与安全层
  三泵互斥 / HX711 / 输入采样 / 看门狗 / ACK
          │          │             │
      泵1/泵2/泵3   称重储液瓶   急停/漏水/卡匣
```

这套上下位机划分是必须保留的：Linux 负责图像、交互和日志；单片机负责确定性的执行互斥、硬超时和失联关泵；物理急停直接切断泵功率，不依赖两者的软件状态。

<!-- pagebreak -->

### 5.1 X5 软件最小集合

| 模块 | 职责 | P0 实现策略 |
|---|---|---|
| `rootscope_core` | admission、状态机、幂等 task_id、取消和恢复 | 单进程 Python，显式枚举状态 |
| `rootscope_serial` | 0xAA55 解析、ACK、身份、新鲜度、重放拒绝 | 独立读线程 + 心跳线程 |
| `rootscope_vision` | 场景卡、基线、目标/非目标 ROI、质量门 | OpenCV；BPU 模型未过门则只作 shadow |
| `rootscope_ui` | 固定装置 Dashboard、曲线、证据和故障原因 | 本地 Web 页面，离线可用 |
| `rootscope_evidence` | 任务配置、遥测摘要、图像摘要、终态和哈希链 | 追加式 JSONL，不覆盖历史 |

P0 不强制拆成多套 ROS 2 包。复用 ROS 2 只在已有部署明显节省时间时采用，不能把中间件本身当创新点。

## 6. 硬件信号连接图

![RootScope 硬件信号连接图](output/rootscope/diagrams/rootscope_signal_wiring.png)

图 1｜RDK X5、USB-TTL、STM32F407、HX711、三路泵驱动和安全输入的信号连接。候选 GPIO 必须在 H0–H4 按实板原理图审计后冻结。

### 6.1 X5 与 F407 串口

| 连接 | 端点 A | 端点 B | 约束 |
|---|---|---|---|
| 上位发送 | USB-TTL TXD | F407 `PD6 / USART2_RX` | 3.3 V TTL |
| 上位接收 | USB-TTL RXD | F407 `PD5 / USART2_TX` | 3.3 V TTL |
| 信号参考 | USB-TTL GND | F407 GND | 必须共地 |
| 供电 | USB-TTL VCC | 不连接 F407 VCC | 禁止双向反灌 |
| X5 端 | X5 USB-A | CH340/同类适配器 | 通过稳定 udev 别名识别 |

通信冻结为 `115200, 8N1`。复用 XRD 已有的 `0xAA55 + type + len + payload + sum8` 帧层、5 Hz 心跳、1 秒失联闭锁和 ACK 状态思想；不是 CRC，也不沿用车辆业务消息。RootScope 必须使用新的 protocol 版本、capabilities 和 build ID。

### 6.2 F407 候选引脚表

| 功能 | 候选引脚 | 电气方向 | 接法/注意事项 |
|---|---|---|---|
| PUMP_Z1 | `PE0` | 输出 | → 驱动器 IN1，默认下拉关断 |
| PUMP_Z2 | `PC13` | 输出 | → 高阻驱动输入；不得直接带负载 |
| PUMP_Z3 | `PC0` | 输出 | → 驱动器 IN3，默认下拉关断 |
| ACT_ENABLE | `PC1` | 输出 | → 三路驱动总许可，与 K1 线圈许可串联 |
| HX711_DOUT | `PB10` | 输入 | HX711 数字输出，按实板电平核验 |
| HX711_SCK | `PB11` | 输出 | HX711 时钟 |
| 卡匣到位 | `PB12` | 输入 | 常闭优先，断线即不安全 |
| 护罩到位 | `PB13` | 输入 | 常闭优先，P0 可与卡匣互锁组合 |
| 漏水片 | `PB14` | 输入 | 独立输入，触发锁存 |
| 急停反馈 | `PB15` | 输入 | 读取 K1/急停辅助触点，不是急停唯一链路 |
| Start | `PC4` | 输入 | 去抖，READY 状态才接收 |
| Reset | `PC5` | 输入 | 长按/显式确认，不能自动清锁 |

以上仅为候选映射。硬件负责人必须根据实际 F407 板、晶振、启动脚、板载外设占用和电压域完成 pin audit 后，在 `ROOTSCOPE_ICD_v1.md` 与固件头文件中一次冻结。旧 XRD 的 `PC9/PD7/PD10` 可保留为未来轴资源，但 P0 不连接任何运动轴。

### 6.3 三泵驱动

- 三路均使用带续流/反向保护的低边 MOSFET 模块或额定匹配的现成驱动模块；
- MCU GPIO 只接逻辑输入，禁止直接驱动电机；
- 驱动输入必须有硬件默认关断；
- 每路泵功率支路独立端子、清晰标号和可替换保险；
- F407 软件和 `ACT_ENABLE` 硬件共同保证单泵互斥；
- 线圈、电机、电源模块的额定值、保险值和线径只能依据最终实物铭牌/数据表冻结，方案不虚构数值。

## 7. 供电、急停与干湿分区

![RootScope 供电与硬急停图](output/rootscope/diagrams/rootscope_power_estop.png)

图 2｜泵电源域由 K1、急停和护罩/卡匣许可硬切；X5、F407 与 UVC 保持上电，以便记录故障和指导复位。

### 7.1 电源树

| 电源域 | 负载 | 断电策略 | 设计原则 |
|---|---|---|---|
| 逻辑域 A | RDK X5、UVC、USB-TTL | 急停时保持 | 使用满足 X5 官方要求的独立稳定供电 |
| 逻辑域 B | F407、HX711、输入传感器 | 急停时保持 | 与泵噪声隔离、单点共地 |
| 执行域 C | 三路泵驱动与泵 | K1 硬切 | 保险、反接保护、端子防水滴 |

RDK X5 的最终供电、电流预算和接口选择必须按所用板卡版本的官方手册核验；[RDK X5 官方规格资料](https://archive.d-robotics.cc/downloads/hardware/rdk_x5/RDX%20X5.pdf) 仅作为选型入口，施工前仍以现场板卡和电源标签为准。

### 7.2 硬件安全链

急停常闭触点、护罩/卡匣许可和 K1 组成泵功率许可链。任何断线或触发都会让 K1 释放。F407 同时读取辅助触点，形成可记录的安全状态；但即使固件死机，物理急停仍能切泵。

复位条件必须全部满足：

- 三台泵实际输出为 OFF；
- 急停旋开，漏水片干燥，卡匣/护罩到位；
- F407 身份、新鲜遥测和称重稳定；
- 人工按 Reset；
- X5 发 `CLEAR_ESTOP`，收到与本轮 seq 匹配的 F407 ACK；
- 复位只回到 READY，不自动恢复旧任务。

### 8.1 总体尺寸与区域

| 项目 | 冻结目标 | 说明 |
|---|---|---|
| 核心框架 | 约 600 W × 360 D × 480 H mm | 2020 型材，桌面固定脚 |
| 光学桥 | 可拆式，前向伸出约 300 mm | 展开总深度约 660 mm |
| 湿区宽度 | 约 380 mm | 卡匣、三深度入口、接水盘 |
| 干区宽度 | 约 160 mm | X5、F407、驱动、电源与急停 |
| 单卡匣外形 | 约 300 × 280 × 42 mm | 有效腔约 260 × 240 × 30 mm，约 1.72 L |
| 出水深度 | 距沙面约 50 / 115 / 180 mm | 分别标记 Z1/Z2/Z3 |
| 相机工作距 | 约 350 ± 20 mm | 最终以完整覆盖卡匣且 ROI 不变形为准 |

尺寸是制造基线，不是精密公差。机械负责人应先用现有泵、瓶、相机和型材实测，再冻结孔位；所有接水盘、保护罩和门开关应优先于外观包覆。

### 8.2 结构连接顺序

1. 底座型材连接湿区和干区，两区之间加竖直隔水板；
2. 湿区底部固定可抽拉接水盘，额定容积至少覆盖一次储液瓶意外泄漏，建议名义容积不小于 3 L；
3. 卡匣座使用底托、两侧导轨和端面止挡建立唯一重复位置；
4. 三根固定出水管从同一侧进入卡匣，在 Z1/Z2/Z3 深度分别固定，出口朝向沙体内部；
5. 三台泵安装于称重托盘外，避免泵振动和管路拉力直接作用于称重瓶；
6. 储液瓶单独置于称重托盘，管路留 U 形松弛段，并配置止回/防虹吸措施；
7. 干区背板固定 X5、F407、驱动模块和端子；电源入口在下方，信号线与泵电源线分束；
8. 可拆光学桥安装单一 UVC、5000 K 左右漫射灯和白背板；相机姿态锁紧后不再移动；
9. 急停安装在右前上方，观众和队员均可触达；Start/Reset 与急停保持明显形态区分；
10. 透明罩覆盖泵和活动管路，卡匣更换路径保持开放但受到位开关监测。

### 8.3 为什么是三泵，而不是一泵三阀

三只独立小泵让通道物理隔离，减少阀时序、串液、残留液和单阀卡滞风险；F407 只需执行严格的单泵互斥。其代价是驱动和管路增加，但三天内更容易台架验证和现场降级：某一路失效时，仍可锁定为单通道演示。

## 9. 物料清单与采购优先级

### 9.1 P0 必须到场

| 类别 | 物料 | 数量 | 选型/验收要求 | 负责人 |
|---|---|---:|---|---|
| 计算 | RDK X5 + 合规电源/存储 | 1 套 | 已有板优先；UVC、串口同时稳定 | 算法 |
| 控制 | STM32F407 开发板 | 1 + 1 备 | 实板引脚可审计，SWD 可恢复 | 硬件 |
| 通信 | CH340/同类 3.3 V USB-TTL | 2 | TX/RX/GND；序列号/udev 可区分 | 硬件 |

### 9.2 P1 可选加分

- BPU 场景分类：只有冻结数据、独立验证和真机日志通过后才从 shadow 升级为正式输入；
- 第二路相机：仅当单相机确实无法同时覆盖场景卡和卡匣时添加；
- 二维码回执：仅承载本轮摘要，不依赖公网；
- 外壳与品牌灯效：完成全部安全和可靠性门后再做。

禁止在 P0 失败时继续追加移动载体、移动轴、多模态大模型或复杂云服务。

## 10. 视觉、计量与控制算法

### 10.1 稳定的 P0 感知

场景选择的可靠路径是三张高对比标记卡，卡片明确代表“夹具 Z1/Z2/Z3”，Dashboard 显示本轮来源为 `tag`。RDK X5 同时运行 BPU/CPU 分类可作为 shadow，但未通过冻结门时不得冒充正式 AI 决策。

卡匣视觉采用固定 ROI：

- 目标 ROI：所选深度出水口周围冻结矩形/多边形；
- 邻层 ROI：用于发现明显越区；
- 背景/边界 ROI：用于检测相机移动、卡匣错位、过曝和遮挡；
- 前后帧均经过颜色/亮度归一化，再计算湿润变化分数和连通区域；
- 阈值只能来自同一批沙、同一光学装置的标定集，不可现场凭感觉不断调到通过。

### 10.2 称重闭环

每轮流程为：稳定窗 → 基线质量 `m0` → 泵水 → 实时质量 `m(t)` → 达到 `m0 - m(t) ≥ target_mass - tolerance` → 立即停泵 → 稳定窗 → 最终质量 `m1`。

下位机负责硬超时和基本阈值，X5 负责配置冻结、趋势检查和证据判断。若质量跳变、反向变化、长期不变、HX711 超时或泵开但质量无合理下降，任务进入 `ABORTED_LOCKED`。

界面默认显示克。只有液体密度、温度范围和本地标定已登记时才可显示近似毫升，并明确标注“估算”。

### 10.3 判定逻辑

```text
positive =
  actuator_ack_fresh
  AND mass_loss_in_frozen_range
  AND target_roi_delta >= target_threshold
  AND neighbor_roi_delta <= spill_threshold
  AND leak_sensor_ok
  AND cartridge_present
  AND camera_quality_ok

if positive:
    TARGET_WETTING_VERIFIED
else:
    ABORTED_LOCKED or MASS_LOSS_VERIFIED_ONLY
```

质量通过但视觉未通过时，只能保留 `MASS_LOSS_VERIFIED`，不能绿色完成。视觉通过但质量未通过同样不能完成。

## 11. F407 协议、状态机与互锁

### 11.1 RootScope 新业务消息

| 方向 | 消息 | 最小字段 |
|---|---|---|
| X5→F407 | `ARM_TASK` | task_id/seq、channel、target_mass、hard_timeout、config_hash 摘要 |
| X5→F407 | `ABORT_TASK` | task_id/seq、reason |
| X5→F407 | `EMERGENCY_STOP` | 无 payload，复用锁存语义 |
| X5→F407 | `CLEAR_ESTOP` | 显式受控复位 |
| X5→F407 | `HEARTBEAT` | seq、上位状态摘要 |
| F407→X5 | `IRRIGATION_TELEMETRY` | task_id、三泵状态、raw/filtered mass、输入位、uptime |
| F407→X5 | `SAFETY_STATE` | estop、leak、cartridge、watchdog、blocked_count |
| F407→X5 | `FIRMWARE_INFO` | protocol、capabilities、build_id、hw_variant |
| F407→X5 | `ACK/ERROR` | ack_for_type、seq、status/reason |

具体 type 值、字节序、整数缩放、范围、无效值、checksum 范围和超时必须由算法与硬件负责人在 H0–H4 共同冻结成一份 ICD。`ARM_TASK` 只接受单一 channel，任何多位泵掩码均返回错误。

### 11.2 状态机

```text
BOOT_LOCKED → SELF_CHECK → READY → TARGET_IDENTIFIED
      → BASELINE_CAPTURED → DOSING_Z1/Z2/Z3
      → SETTLING → VERIFYING → TARGET_WETTING_VERIFIED

任意安全故障 → SAFE_STOP → ABORTED_LOCKED
ABORTED_LOCKED --人工排障+Reset+ACK--> SELF_CHECK
```

### 11.3 F407 必须独立保证的约束

- 上电三泵全关、K1 许可关闭；
- 任意时刻最多一台泵开启；
- 5 Hz 心跳超过 1 秒未更新时关泵并锁存；
- 每个任务有独立 hard timeout，X5 卡死也会停泵；
- 急停、漏水、卡匣/护罩断开均立即撤销许可；
- 未知固件身份、旧 task_id、重复 seq、越界质量目标和非法通道一律拒绝；
- 清急停必须显式命令 + 本地安全条件 + ACK；
- 旧任务在重启后不恢复，泵不会自动续跑。

## 15. 展位与路演

### 15.1 30 秒讲稿

“传统灌溉容易看到阀门开了，却看不到水是否真正到达目标区域。RootScope 用 RDK X5 在本地识别演示场景，STM32 在急停、漏水、卡匣、通信和称重都可信时，只打开浅、中、深中的一个固定通道。储液质量达到目标后自动停泵，固定相机再验证目标区域是否出现新的湿润团。只有计量和视觉都通过才显示绿色；拔线、移开卡匣或按急停，它会关泵并锁存。我们不虚构节水率，而是先把可测、可拒绝的灌溉执行核心做实。”

### 15.2 海报只放四层

1. 痛点：**开泵 ≠ 定量 ≠ 到达目标区域**；
2. 装置：一张真实正面照片，标出 X5、F407、称重瓶、三泵、卡匣、相机和急停；
3. 证据链：`场景 → 安全门 → 单通道 → 称重 → ROI → 回执`；
4. 诚实边界：已验证、未验证、下一阶段各一列。

展台左侧放透明卡匣与相机，右侧放 Dashboard，中间留场景卡和 Start；急停始终露出。水路、擦拭、备卡匣和工具放桌下，观众不触碰电控端子。

### 15.3 高频 FAQ

**为什么不做会跑的灌溉小车？**

移动不证明给水更准确，却会把 72 小时耗在运动与定位上。RootScope 先把“选层—定量—到达验证—安全拒绝”做成稳定核心，未来可接温室支路、固定灌溉桩、轨道设备或移动平台。

**这还是机器人吗？**

它具有感知、决策、执行、反馈和安全状态，是固定自主设备。对外优先称“固定式根区灌溉舱/端侧灌溉控制器”，不依赖轮子来证明机器人价值。

**AI 在哪里？是不是标记卡 Demo？**

可靠 P0 用标记卡定义场景并明确显示来源；X5 同时负责固定视觉前后验证、状态决策、交互和证据。只有 BPU 分类在冻结数据和真机上通过门槛后才成为正式感知来源，否则显示 `shadow`。

**为什么需要 X5 和 F407 两块主控？**

X5 适合图像、BPU、Dashboard 和证据；F407 适合确定性的泵互斥、硬超时和失联停机。X5 重启时 F407 仍能关泵，急停还可直接切执行电源。

**能证明节水吗？**

不能用三天装置给出节水率。本次只证明受控夹具中的定量与目标区域变化；节水、作物健康和产量需要长期对照和真实田间数据。

固定框架和卡匣属于三天内难以从零可靠加工的部分，应在赛事规则允许范围内提前完成或至少准备标准型材、透明板、导轨、接水盘和可快速装配件，并在预制资产清单中如实披露。三天的现场价值应放在新的灌溉固件、称重/视觉闭环、整机集成、失败注入与产品化展示，而不是切型材和反复补漏。

### 16.3 最终一句话

> RootScope 不是一辆缩小版竞赛小车，而是一台让“水是否按量到达目标根区”在 45 秒内可见、可测、可失败验证的固定端侧灌溉舱。
